# Data Model: Offline-First POS Architecture

## LocalTransaction

**Purpose**: Locally authoritative record of a POS transaction.

**Fields**:
- `id`: UUID v4 string, generated before local commit.
- `deviceId`: Stable POS device identifier.
- `branchId`: Business branch/location identifier.
- `transactionType`: `sale`, `refund`, `inventory_adjustment`, `shift_close`.
- `items`: Snapshot of sold or moved items.
- `totals`: Subtotal, tax, discount and final amount.
- `paymentSummary`: Payment method and captured amount metadata.
- `localVersion`: Monotonic local integer for mutation tracking.
- `createdAtLocal`: Device timestamp when created.
- `updatedAtLocal`: Device timestamp when last changed.
- `syncState`: `pending`, `syncing`, `synced`, `failed`, `conflict`.
- `cloudReceiptId`: Nullable cloud receipt after accepted sync.

**Validation Rules**:
- `id` MUST be UUID v4.
- `totals.finalAmount` MUST be non-negative for sales.
- `syncState` MUST NOT be `synced` unless `cloudReceiptId` is present.
- Critical fields are immutable after sync except through compensating transactions.

**State Transitions**:
- `pending -> syncing -> synced`
- `pending -> syncing -> failed -> pending`
- `pending -> syncing -> conflict`

## SyncOperation

**Purpose**: Durable local queue item for cloud delivery.

**Fields**:
- `id`: UUID v4 string for the queue operation.
- `transactionId`: UUID v4 of the LocalTransaction.
- `operationType`: `upsert_transaction`, `void_transaction`, `inventory_adjustment`.
- `payload`: Canonical JSON payload sent to Lambda.
- `payloadHash`: Hash used to detect accidental mutation.
- `idempotencyKey`: Usually the transaction UUID v4.
- `attemptCount`: Number of delivery attempts.
- `nextAttemptAt`: Timestamp for retry scheduling.
- `lastErrorCode`: Nullable last sync error.
- `state`: `pending`, `in_flight`, `accepted`, `failed`, `conflict`.

**Validation Rules**:
- `idempotencyKey` MUST be stable across retries.
- `payloadHash` MUST match the payload before sending.
- `attemptCount` MUST increment only after an attempted send.

## PrintJob

**Purpose**: Local durable request to print a ticket or kitchen command.

**Fields**:
- `id`: UUID v4 string.
- `transactionId`: Related LocalTransaction UUID.
- `printerDeviceId`: Target PrinterDevice ID.
- `jobType`: `receipt`, `kitchen_order`, `shift_report`.
- `escposPayload`: Bytes or encoded representation of commands.
- `state`: `queued`, `printing`, `printed`, `failed`.
- `attemptCount`: Print attempts.
- `lastError`: Nullable adapter error.

**Validation Rules**:
- Print job MUST be persisted before attempting device I/O.
- ESC/POS payload MUST be generated by the shared formatter.

## PrinterDevice

**Purpose**: Configured thermal printer and transport metadata.

**Fields**:
- `id`: UUID v4 string.
- `name`: User-visible printer name.
- `platform`: `windows`, `android`.
- `transport`: `usb`, `bluetooth`, `network`.
- `address`: USB identifier, Bluetooth MAC/name or host:port.
- `capabilities`: Paper width, encoding and cutter support.
- `isEnabled`: Boolean.

**Validation Rules**:
- Windows devices MUST use `usb` transport in this baseline.
- Android devices MUST use `bluetooth` or `network` transport in this baseline.

## POSDevice

**Purpose**: Registered physical POS device that can keep operating offline after one online
registration.

**Fields**:
- `deviceId`: Stable UUID assigned during online registration.
- `branchId`: Business branch/location identifier.
- `registeredAt`: Server or device timestamp for initial registration.

**Validation Rules**:
- `deviceId` MUST be persisted locally before offline transactions are allowed.
- Offline transactions MUST include the same `deviceId` across app restarts and sync retries.

## CachedUserSession

**Purpose**: Local offline authorization state for a previously authenticated user.

**Fields**:
- `userId`: Authenticated user identifier.
- `roleIds`: Cached roles or permissions.
- `pinHash`: Local hash used for offline PIN unlock.
- `cachedAt`: Timestamp when roles were cached.
- `expiresAt`: Timestamp after which online revalidation is required.

**Validation Rules**:
- Offline POS actions MUST require PIN or biometric unlock.
- Cached roles MUST limit available actions while offline.

## CloudTransaction

**Purpose**: PostgreSQL representation of an accepted local transaction.

**Fields**:
- `transaction_id`: UUID primary or unique key from LocalTransaction.
- `device_id`: Source device.
- `branch_id`: Business branch.
- `transaction_type`: Transaction type.
- `payload`: Accepted canonical transaction JSON.
- `payload_hash`: Hash received from client.
- `accepted_at`: Server timestamp.
- `source_created_at`: Client creation timestamp.

**Validation Rules**:
- `transaction_id` MUST be unique.
- Replays with the same `transaction_id` and same hash return the original receipt.
- Replays with the same `transaction_id` and different hash create a conflict response.

## SyncReceipt

**Purpose**: Cloud acknowledgement returned to the client.

**Fields**:
- `receipt_id`: UUID.
- `transaction_id`: UUID v4 accepted transaction ID.
- `status`: `accepted`, `duplicate`, `conflict`.
- `accepted_at`: Server timestamp.
- `cloud_version`: Monotonic cloud version.

## ConflictRecord

**Purpose**: Audit and support record for operations that cannot be reconciled automatically.

**Fields**:
- `id`: UUID.
- `transaction_id`: Related UUID.
- `reason`: Conflict reason code.
- `local_payload`: Client submitted payload or reference.
- `cloud_payload`: Existing cloud payload or reference.
- `detected_at`: Server timestamp.
- `resolution_state`: `open`, `resolved`, `ignored`.

## Relationships

- `LocalTransaction` has zero or more `SyncOperation` records.
- `LocalTransaction` has zero or more `PrintJob` records.
- `LocalTransaction` references one persisted `POSDevice.deviceId`.
- `PrintJob` targets one `PrinterDevice`.
- `CloudTransaction` corresponds to one accepted `LocalTransaction` by UUID.
- `SyncReceipt` acknowledges one `CloudTransaction` or duplicate replay.
- `ConflictRecord` references a transaction UUID that needs explicit resolution.
