A practical mental model

One repository.
Many safe desks.

A branch is a named line of changes. A worktree is a separate folder where one branch can be edited without stepping on another agent.

The difference

Branches are history.
Worktrees are workspace.

A lightweight pointer to a line of commits. Think: “the backend version of Feature 018.”

Reviewers do not need a writing desk

They inspect branches, diffs, plans, and test output. This avoids five branches when only three apps are changing.

If all five must write

Create five isolated worktrees. Split by non-overlapping file ownership first; otherwise keep the extra agents read-only.

Start sequence

Set the desks up before dispatching anyone.

git switch main git pull origin main make team-setup FEATURE=018-stock-receiving # Then dispatch one writer per app boundary: ./scripts/agent-team.sh dispatch agy backend "Implement receiving API + migration. Run backend tests." ./scripts/agent-team.sh dispatch opencode admin "Implement receiving UI. Run admin build/tests." ./scripts/agent-team.sh dispatch codex pos "Implement POS receiving view. Run flutter analyze."

Before editing, each writer declares its scope in .claude/workspaces.md and commits/pushes that declaration.

During work

Each agent owns a narrow slice.

Writer checklist

  • Stay inside your app folder.
  • Commit small working increments.
  • Push your branch.
  • Never edit another agent’s branch/worktree.

Coordinator checklist

  • Watch scope declarations.
  • Resolve shared-file conflicts before edits.
  • Run cross-app checks after work is merged.
  • Own the single migration window.

Database migrations are the exception: one agent runs them, after declaring the intent and waiting for the coordination window.

Remember this

Branches prevent history collisions.
Worktrees prevent file collisions.

Do

  • One writer = one branch + one worktree.
  • Split work by app boundary.
  • Use reviewers for parallel thinking without parallel edits.
  • Merge only after checks pass.

Do not

  • Run multiple agents in the same folder.
  • Let agents edit shared files without coordination.
  • Run two migrations at once.
  • Merge an entire branch when it includes unrelated commits.
